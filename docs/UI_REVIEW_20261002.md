# Interface review — 2026-10-02 (#90)

The daily path should be open a session, type, scroll and add a related session.
The current screen gives rare controls too much space and uses ambiguous lifecycle labels.

## Confirmed problems repaired in 0.22

| Finding | Repair |
| --- | --- |
| A default global 12-session cap rejects new sessions | Main configuration raised to 24; Settings shows the configured value. Only running/reserved sessions consume admission capacity. Staging and workflow-specific limits stay separate. |
| Close hides the terminal without detaching its tmux client | Hidden views close their browser WebSocket; the underlying session stays alive. Reopening reconnects and keeps the composer draft. |
| Stop is hidden inside details; on phones the terminal covers it | Stop session is in the session heading and terminal header. Close terminal is separately named. Only Stop asks for destructive-action confirmation. |
| A background refresh can show a stopped session as still open | Close the view immediately after successful Stop, then fetch fresh state after any earlier read finishes. |
| Stop promises to retain a transcript but kill never saves it | Save private bounded recent output before killing. If capture fails, leave the process running and report the error. Existing files/worktrees remain. |
| Typing and tmux history scrolling require separate modes | Type & scroll is the embedded default. Wheel and touch read history; typing exits history before sending bytes. Coalesce scroll bursts to avoid excessive tmux subprocesses. |
| A newly connected iframe takes keyboard focus from the tree | Embedded startup no longer focuses the terminal automatically. Click/tap the terminal or composer to type; reconnect does not steal composer focus. |
| Full-screen mobile terminal can leave the background moving or be obscured by the keyboard | Lock the background and use the parent visual viewport for the terminal overlay. Physical-device keyboard behavior still needs user feedback. |

## Proposed next interface pass

1. **A compact session tree beside the terminal.** Show session name, harness and one useful state. Put Add session on the selected node; reveal the other node actions through a menu. On phones, open the tree as a drawer so it does not push the terminal down.
2. **One terminal toolbar.** Keep Stop, Close terminal and expand visible. Keep Copy available; group reconnect, load brief, special keys and diagnostic controls under More. Preserve direct terminal typing and an optional composer for multiline/mobile input.
3. **One details drawer.** Task brief, files, history, skills and configuration become sections inside Details. Results and scheduling appear only when deliberately opened, rather than competing with the terminal.
4. **Separate active work from history.** Default the list to running sessions and actionable attention; put stopped sessions in History. Keep full tree relationships available. Stopping one session should never silently stop its children or delete its workspace.

These are proposals for the broader redesign, not a new mandatory workflow. This repair
moves Stop out, collapses the existing details section, and fixes interaction mechanics.
It retains the iframe boundary: it is not itself the fault. Invisible attached clients,
focus transfer, split input modes and viewport coordination were the concrete problems.

## Limits

Each tmux pane shares copy mode across attached clients. Two devices scrolling the same
pane can affect one another; independent per-device history would require a larger
terminal design change. The saved transcript is bounded recent terminal output, not the
complete native model conversation. Raising the session cap does not make model-process
memory unlimited; inactive sessions can be stopped without deleting their files.
